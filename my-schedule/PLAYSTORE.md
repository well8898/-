# 플레이스토어 비공개 테스트 올리기

「오늘 현장」 앱을 구글 플레이 **비공개 테스트**로 배포하는 순서입니다.
검색에 나오지 않고, 초대한 사람(구글 그룹 회원)만 받을 수 있습니다.

## 준비된 것

| 무엇 | 어디 |
|---|---|
| 플레이스토어용 앱 빌드 (`play` 버전: 스토어가 업데이트, 앱이 스스로 APK 를 받지 않음) | `android/app/build.gradle` |
| 안드로이드 16(API 36) 기준, 새 앱 아이콘 | 같은 곳 |
| 플레이스토어용 파일(AAB) 자동 빌드 — 업로드 키가 등록돼 있을 때만 서명 | `.github/workflows/build-widget-apk.yml` |
| 개인정보처리방침 페이지 | https://my-schedule-henna.vercel.app/privacy |
| 아이콘 512, 그래픽 이미지 1024×500, 휴대폰 스크린샷 5장 | `store/` |
| 업로드 키 (저장소에는 없음 — 담당자에게 따로 전달) | `play-upload.jks` + 비밀번호 |

링크로 받는 APK(지금 방식)는 그대로 계속 만들어집니다.

## 1. 구글 플레이 개발자 등록 (담당자)

1. https://play.google.com/console 에서 **개인** 계정으로 가입 (등록비 $25, 한 번)
2. 신분증 인증, 휴대폰 인증
3. 개발자 이름·연락처 이메일은 스토어에 표시됩니다

## 2. 업로드 키를 GitHub 에 등록 (한 번)

GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret** 에서 두 개를 만듭니다.

| 이름 | 값 |
|---|---|
| `PLAY_KEYSTORE_B64` | `PLAY_KEYSTORE_B64.txt` 파일 내용 전체 |
| `PLAY_KEYSTORE_PASS` | `PLAY_KEYSTORE_PASS.txt` 파일 내용 |

그다음 **Actions → 위젯 앱 빌드 → Run workflow** 를 누르고, 끝나면 그 실행 화면 아래 **Artifacts → playstore-aab** 를 받습니다(zip 안에 `today-site-play.aab`).

> 업로드 키 파일(`play-upload.jks`)과 비밀번호는 PC 등 안전한 곳에 따로 보관하세요. 저장소·카톡에 올리지 마세요.
> 잃어버려도 플레이 콘솔에서 업로드 키 재설정을 요청할 수 있습니다(앱 서명 키는 구글이 보관).

## 3. 앱 만들기

플레이 콘솔 → **앱 만들기**

- 앱 이름: `오늘 현장 - 승강기 검사 일정`
- 기본 언어: 한국어
- 앱 / 무료
- 선언 체크 후 만들기

## 4. 앱 설정 (대시보드의 「앱 설정」 항목)

| 항목 | 답 |

| 개인정보처리방침 | `https://my-schedule-henna.vercel.app/privacy` |
| 앱 액세스 | 모든 기능을 제한 없이 이용 가능 (로그인 없음). 설명: 「첫 화면에서 지사를 고르고 이름을 누르면 일정이 나옵니다. 일정표가 있는 지사(예: 고양파주지사)를 고르세요.」 |
| 광고 | 광고 없음 |
| 콘텐츠 등급 | 카테고리 「유틸리티, 생산성, 커뮤니케이션 또는 기타」 → 폭력·성·언어·약물·도박 질문 모두 **아니요**, 사용자 간 소통·콘텐츠 공유는 **아니요**(정해진 일정표만 공유), 위치 공유 **아니요**, 디지털 상품 구매 **아니요** |
| 타겟층 | 만 18세 이상 |
| 뉴스 앱 / 정부 앱 / 금융 / 건강 | 모두 아니요 |

### 데이터 보안 (Data safety)

- 사용자 데이터를 수집하거나 공유하나요? → **예**
- 전송 중 암호화? → **예** (HTTPS)
- 삭제 요청 방법 제공? → **예** (개인정보처리방침의 이메일 요청)

| 데이터 유형 | 수집 | 공유 | 용도 | 필수 |
|---|---|---|---|---|
| 개인 정보 → **이름** | 예 | 아니요 | 앱 기능 | 예 |
| 앱 활동 → **기타 사용자 생성 콘텐츠** (올린 일정표 내용) | 예 | 아니요 | 앱 기능 | 아니요 (올리는 사람만) |

- 위치, 연락처, 사진, 기기 ID, 앱 사용 기록 등은 **수집 안 함**
- 지도·경로 API(카카오·티맵)와 서버(Vercel)는 「서비스 제공업체」라 공유에 해당하지 않음

## 6. 비공개 테스트 만들고 올리기

1. 테스트 및 출시 → **테스트 → 비공개 테스트** → 트랙 만들기 (예: 「지사 테스터」)
2. **국가/지역**: 대한민국
3. **테스터**: Google 그룹 이메일 추가 (예: `오늘현장-테스터@googlegroups.com`)
   - https://groups.google.com 에서 그룹 만들기 → 「누구나 가입 가능」 또는 「가입 요청」으로 설정
4. **새 버전 만들기** → 「Google Play 앱 서명」 사용 → `today-site-play.aab` 업로드 → 출시 노트 입력
5. **검토 → 출시 시작** (구글 검토 며칠)
6. 승인되면 **테스터 참여 링크(웹)** 를 복사해 그룹 가입 링크와 함께 카톡으로 보냅니다

테스터 순서: 구글 그룹 가입 → 참여 링크에서 「테스터 되기」 → 플레이스토어에서 설치

## 7. 다음 버전 올리기

1. `android/app/build.gradle` 의 `versionCode` 를 1 올리고 푸시 (또는 Actions → Run workflow)
2. Actions → Artifacts → `playstore-aab` 받기
3. 비공개 테스트 → 새 버전 만들기 → AAB 올리기 → 출시

테스터 휴대폰은 플레이스토어가 알아서 업데이트합니다.

## 알아 둘 점

- **링크로 받은 APK 를 쓰던 분**: 서명이 달라 그 위에 덮어 설치되지 않습니다. 한 번 앱을 지우고 플레이스토어에서 설치한 뒤, 위젯을 다시 추가하면 됩니다(지사·이름은 다시 고름).
- **정식 출시를 하려면**: 개인 계정은 테스터 12명 이상이 14일 동안 비공개 테스트를 해야 정식 출시 신청이 가능합니다. 비공개 테스트로만 계속 써도 됩니다.
- 위 숫자·조건은 구글 정책에 따라 바뀔 수 있으니 콘솔 안내를 우선하세요.
